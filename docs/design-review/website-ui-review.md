## Priority ordered fixes

1. **Required: update first-recording instructions for BAPS 1.9.** Setup step 02 still says “Start with base.en, or large-v3-turbo for best quality,” but `Prefs.transcriptionEngine` defaults to `baps`, and Settings recommends BAPS Whisper at approximately 1.6 GB. Suggested copy: “Open Settings → Transcription. Download BAPS Whisper (about 1.6 GB), recommended for English with Gujarati and Sanskrit vocabulary written in Latin letters. Choose Whisper for other languages or translation.” Parakeet can remain the fast plain-English alternative if there is room; avoid turning this row into a model catalog. Tell users the first BAPS load may take a few minutes while it compiles for the Neural Engine. The linked README first-run guide is also stale and should be aligned in a separate authorized docs change. `SettingsView` explicitly says BAPS skips the AI review pass: step 03 should say Ollama is optional for summaries and AI cleanup on supported paths, rather than suggesting BAPS requires it for useful transcription. **Targets:** `website/index.html` setup rows; source evidence `Prefs.swift:20–27`, `SettingsView.swift:92–115` and `:232`. This is the primary setup blocker visible in the supplied screenshot.

2. **Required: qualify local processing claims consistently.** Hero says “No cloud,” feature introduction says “Every step runs on your Mac,” and privacy says transcripts/summaries stay local, while the same page correctly acknowledges opt-in hosted summaries. Native custom/Ollama URLs may also be remote. Suggested hero: “Record and transcribe on your Mac. Summarize locally by default. No account.” Privacy explanation: “Audio stays on your Mac. With a local summary model, transcripts and summaries stay here too. If you configure a hosted provider, transcript text is sent to that endpoint.” Offline operation requires models to have been downloaded. Keep the strong audio-local headline; make the supporting claims conditional where the actual configuration is conditional. **Targets:** hero lede, features introduction, privacy paragraph; verify against effective provider endpoint behavior rather than provider name alone.

3. **Required: make setup instructions readable whenever visible.** `.js .step` starts at opacity 0.4, and the observer’s negative 18% bottom margin leaves the visible third row washed out until it moves farther into view. Confirmed in `/tmp/wffl-senior-setup-settled.png`: “Add a local model” and its useful optionality explanation are on screen but appear disabled. Keep functional text at full opacity. Animate only the decorative numeral or a small transform; alternatively reveal as soon as the row enters the viewport. Do not dim actual instructions below contrast merely to show scrolling progress. **Targets:** setup `.step` CSS and IntersectionObserver reveal treatment. This does not require changing the generous row spacing.

4. **Recommended: replace “Cancelled” privacy pills with stable capability states.** In the mobile privacy panel, “Cancelled” reads like a job was cancelled or an operation failed; cloud transcription/account/telemetry were never started. Use “On-device” for cloud transcription, “Not required” for account sign-in, and “None” for telemetry. Leave “Off by default” for optional hosted summaries. Use neutral/hollow dots for these static states so ember retains its live meaning. **Targets:** privacy table pill text/styles. The panel’s type and stacked mobile hierarchy are otherwise clear.
